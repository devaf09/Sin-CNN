# RESULTS — opticlm 実験記録

## 現在の結論 (2026-10-13 更新。CC-100 日本語 1000万文字、文書単位で検証)
1. **単独のリザバーが、同じバイト数の n-gram に勝つ帯は無い** (1M・10M文字とも)。
   10M では n-gram の表 (文脈3, 15MB) がリザバーの重み (13MB) を超えたが、剪定した n-gram (文脈3 剪定2, 5.5MB: acc1 40.2 /
   nll 3.024) がリザバー (D=16385, 13MB: 35.0 / 3.257) を全指標で上回る。データを10倍にしても、リザバーの伸び (acc1 +0.8) は
   n-gram (+3.6) より小さい。D=24337 にしても 36.3 / 3.160 (+1.2) で、差は埋まらない。
   → **「軽さ」「固定メモリ」は主張しない。** README の位置づけを「物理実装の研究用モデル + n-gram の混合補助」に改めた。
2. **混合の補助としての優位は、強い n-gram (Kneser-Ney) 相手では消えた。** WB 相手では「0.6〜1.1MB のリザバーを足すと nll -0.05、
   同サイズの n-gram より良い」だったが、KN 相手では -0.01 程度で、同サイズの n-gram を足すのと差がない (2026-10-13)。
   残るのは「合計 1〜3MB の小予算で、強く剪定した n-gram にランク32 (0.56MB) を足す」帯だけで、これも剪定法次第 (未確定)。
   単独でも、KN にはほぼ全構成で支配される (KN 文脈3 剪定2 5.5MB: 40.4 / 2.875 vs リザバー 13MB: 35.0 / 3.227)。
3. **物理実装に向けた成果: W は 4〜5bit で足りる。** 4bit が壊れる原因はバイアス行 (他の行の 44 倍) と列内の外れ値。
   256行ごとのグループスケールで、5bit 無劣化、4bit で acc1 -0.2 / nll +0.03 (現行方式は 4bit で acc1 -7.6)。opticlm に組み込み済み。
4. 較正の改善 (binpow: 確信度ビン × power × 頻度^β) で nll -0.03〜-0.04 (交差当てはめで確認)。既定の calibrate() に入れた。
   n-gram との nll の差 0.4 の大部分は較正ではなく順位 (acc1) の差から来ている。
5. 特徴の増強 (参照光・bag 長距離) は、全窓 (15.8万窓) で見ても D=4096・16384 とも効果なし。既定 (オフ) のまま。
6. 厳密性 (追加学習・取り消し・融合) は従来どおり。selftest は全変更の後で全 OK (GPU 含む)。
7. **容量の壁は特徴の種類ではなく、線形読み出しの容量 (D×語彙)**。光学の特徴は同じ D のランダムフーリエ特徴と同等〜わずかに上
   (acc1 +0.3〜0.4)。高次の相互作用を足す2段カスケードは 1M・10M とも悪化。回折は必須 (無いと acc1 24.8 → 16.7)。
8. **量子化の頑健性は再現した**: 検証窓 20万・D 2通り・seed 2通りで、5bit g256 は nll +0.007、4bit g256 は +0.025。
   W の素子ばらつき 10% で +0.014、推論時の検出器 (光子100・ADC 6bit) で +0.016。ゲインは「露光ごと + バイアス別」で崩れが直る。
   ただし D=4097 では 4bit で +0.07 と悪化が大きい (小さい D なら 5bit)。
9. CPU の並列学習 (fit_parallel、優先度を下げて動く) を追加。4プロセス×2スレッドで 2.1 倍。結果は一括学習と一致 (2.4e-16)。

## 未解決・次の一手
- **n-gram 側の比較相手を強くする (公平性)**: 今の n-gram は Witten-Bell で、剪定すると nll が大きく悪化する。Kneser-Ney と
  相対エントロピー剪定を入れると、小さい帯 (575KB) で唯一残った「nll はリザバーが良い」点も逆転する可能性が高い。
  混合補助の結論 (キュー2) も、強い n-gram 相手で再確認が必要。
- **混合補助としての最適化**: 混合に効くのは低ランク (ランク64) の粗い情報だった。「n-gram に足す専用」の小さなリザバー
  (D 小・ランク低・4bit g256) をサイズ最小で設計できる。混合の重みを確信度ビンごとに変える (binpow と同じ考え) のも有望。
- D=32768 以上: A を CPU に置き、GPU では fp32 バッファに溜めて CPU の fp64 に足す改修が要る。得るものは acc1 +1 程度の見込み。
- 1M・D=16385 で train 38.6 / val 35.6 と過学習が始まっている。大きい D はデータが多いときだけ意味がある。
- リポジトリ全体の批判は REVIEW_repo.md。02 系の伝播 (fftshift の誤り) は、光での再現を目指すなら直す必要がある (03_Opticlm 外なので未修正)。
- C2 (分野ごとのパッケージ): 分野の異なるコーパスが要る。精度ではなく「厳密な融合・取り消し」の実用例として価値がある。
- 要判断の項目: なし (元に戻せない変更はしていない。opticlm.py の各変更前の版は backup/ にある)。

### 同じサイズ帯での勝敗 (リザバー D=16385 W8bit = 13.2MB の帯)
- n-gram 文脈3 剪定なしの表 (15.2MB) が、ちょうどリザバーの重み (13.2MB) を超える規模になった。狙いどおりの帯。
- それでも 13.2MB 以下の n-gram がリザバーを全指標で上回る: 文脈3 剪定2 (5.5MB) は acc1 40.2 vs 35.0、nll 3.024 vs 3.257。
  n-gram に不利な 8B/項目 の見積もりでも 文脈3 剪定2 (11.1MB) が支配する。
- bench の支配判定: 4B/項目で 15/16、8B/項目で 13/16 が支配される。支配されない構成は全て「どの n-gram より小さい」
  (最小の n-gram 点 908KB / 8B見積もりで 1.81MB) ために比べる相手がいないだけのもの (575KB〜1.15MB の低ランク W)。
  この帯も、剪定を強めた n-gram を足して確認中 (キュー2 の実行に --ng-min 20,50,100 を含めた)。

### 解釈
- **データを10倍にすると n-gram は acc1 +3.6 伸び、リザバーは +0.8 しか伸びない。差は 2.3 → 5.1 ポイントに広がった。**
  リザバーは train≈val の容量不足で、D が同じならデータを増やしても伸びが小さい。「固定メモリ」は、
  固定したぶん大量データの恩恵を受けられないことの裏返しになっている。
- n-gram は剪定で小さくでき、剪定しても acc1 はほぼ落ちない (文脈3: 剪定なし 40.2 / 剪定2 40.2 / 剪定5 39.3)。
  つまり n-gram の表は「データ量に比例して大きくなる」が、同じ大きさに剪定した n-gram の方がまだ強い。
- 注意 (n-gram 側に不利な点): Witten-Bell の剪定は nll を大きく悪化させる (文脈4 剪定10 で 4.013)。Kneser-Ney 等にすれば
  n-gram はさらに強くなる見込み。つまりこの比較はリザバーに甘い側であり、結論 (n-gram が勝つ) は変わらない。
- 混合: リザバー(D=16385 W16bit) + n-gram文脈3 で nll 2.781 (単独の良い方 2.837 より -0.056)。1M のときの -0.108 から縮小。
- **判断の指針: 「同じサイズ帯の n-gram がリザバーに負ける構成」は出なかった → 「軽さ」「固定メモリ」は主張しない側へ。**

次の一手: キュー2 (混合の公平な比較) を実行中。結果を見て README の位置づけを書き直す。

## 2026-10-12 20:10〜20:37 キュー2: 混合の公平な比較 (10M文字) — 26分
コマンド: `python opticlm.py bench cc100_v10m.txt --d 8192,16384 --ng-min 1,2,3,5,10,20,50,100 --gpu` (ログ logs/bench_10m_mix.log)

サイズは n-gram に有利な 4B/項目 で数えた。混合の重みは検証窓で 0.05 刻みに選ぶ (1パラメータなので選び過ぎの影響は小さい)。

### (1) 基準 n-gram 文脈3 剪定なし (15.2MB, nll 2.837) に「1つ足す」: 追加バイト数で揃えて比較
| 追加するもの | 追加サイズ | 混合 nll | 基準からの差 |
|---|---|---|---|
| n-gram 文脈4 剪定100 (この帯で最良の n-gram) | 575KB | 2.817 | -0.020 |
| **リザバー D=8101 W ランク64 (8bit)** | 575KB | **2.789** | **-0.048** |
| **リザバー D=16385 W ランク64 (8bit)** | 1.11MB | **2.785** | **-0.052** |
| n-gram 文脈2 剪定3 | 1.75MB | 2.816 | -0.021 |
| n-gram 文脈2 剪定2 | 2.36MB | 2.809 | -0.028 |
| n-gram 文脈2 剪定1 (足す n-gram で最良) | 4.51MB | 2.792 | -0.044 |
| リザバー D=16385 W 8bit | 13.2MB | 2.781 | -0.056 |
| n-gram 文脈4 剪定1 | 32.6MB | 2.824 | -0.013 |
- **小さい予算 (0.5〜4MB) で足すなら、リザバーの方が n-gram より効く** (-0.05 vs -0.02〜-0.03)。差 0.03 nat は、
  同じ窓での対比較の標準誤差は約 ±0.005 (mix_compare に対比較の標準誤差を追加し、200k文字/D=257 の小試験で±0.004〜0.005 を確認。窓数は同じ約2万)。差 0.03 はその約6倍で有意。
- 4.5MB 以上を足せるなら n-gram 文脈2 剪定なしでもほぼ追いつく (-0.044 vs -0.050〜-0.056、差 0.01 以内は「差なし」扱い)。
- リザバーの効き目は D や W の精度にほとんど依らない (ランク64 でも -0.048)。混合に効くのは「低ランクの粗い情報」。

### (2) 2モデル混合の全ペア (384通り) で、リザバー入りの混合がサイズ以下の n-gram 同士の混合に負けるか
- 363/384 が負ける。負けない 21 通りも、ほとんどは差 0.001〜0.007 (= 誤差の範囲)。
- 最良: n-gram 同士 (文脈2 剪定なし + 文脈4 剪定なし, 37MB) **2.769** < リザバー入り (文脈3 + D=16385, 41.6MB) 2.781。
- つまり「どの組み合わせでも最良の nll を出したい」なら n-gram 同士で十分。リザバーの価値は「小さな追加で効く」点に限られる。

### (3) 小さいサイズ帯の単独比較 (剪定 20/50/100 の n-gram を追加)
- 575KB 帯: n-gram 文脈2 剪定100 (534KB) は acc1 31.8 / nll 4.217、リザバー D=8101 ランク64 (575KB) は 29.7 / 3.986。
  acc1 は n-gram、nll はリザバー。どちらも他方を支配しない (bench の判定でも唯一「支配されない」)。
  ただし n-gram の nll が悪いのは Witten-Bell + 強い剪定のせい (剪定で消えた項目の確率質量の扱いが雑) の可能性が高く、
  剪定に強い平滑化 (Kneser-Ney, 相対エントロピー剪定) を入れれば逆転しうる。勝ちとは書かない。

### 解釈と判断
- キュー1と合わせて: **リザバー単独が同じバイト数の n-gram に勝つ帯は無い**。売りにできるのは
  「n-gram に 0.5〜1MB 足すだけで nll が約 0.05 下がる、n-gram 同士より安い補助」。
- 判断の指針の「出ない」側として、README の位置づけを書き直す (この後)。

## 2026-10-12 21:10〜21:50 キュー4: 較正の改善 → 新しい較正器 binpow を calibrate() に追加
方法: exp_calib.py で検証窓のスコアを保存 (dump)、写像を CPU で比較。**検証窓を交互に半分ずつ「当てはめ用 / 評価用」に分け、

## 2026-10-13 アイディア C3: 光学の特徴 vs ランダム特徴、2段カスケード (exp_features.py)
同じ D・同じ露光 (scales 1〜4 の入れ子の窓)・同じ閉形式の読み出しと較正で、特徴の作り方だけを変える。検証は先頭2万窓。
- optics: 現行 / nodiff: 位相板と伝播なしで |Σ ホログラム|² / cascade:α: 1段目の強度を exp(iαI) で2段目の位相にして、別の位相板+伝播のあと検出
  (3文字以上の相互作用が生まれる) / rff:σ: cos(σΣg+b) のランダムフーリエ特徴 / prod: cos(Σθ+b) (窓の完全一致 = ハッシュ化した n-gram)。
- 動機: 位相板と伝播は電場について線形なので、1段の強度検出の特徴は「文字の2つ組の相互作用」までしか持たない。
  n-gram (文脈全体の一致) との容量の差がそこから来るなら、高次を足すカスケードで縮むはず、という仮説。

- **回折 (位相板+伝播) は必要**。無いと1文字の露光が |位相|²=1 で情報を持たず、大きく悪化する (私の事前の見立て
  「線形なユニタリの構造は効かない」は誤りだった。回折は、各文字の位相パターンを強度の模様 (スペックル) に変える役をしている)。
- **高次の相互作用 (カスケード、prod) は 1M文字では効かない**。α を大きく (非線形を強く) するほど悪い。
  容量の差が「2次止まり」だから、という仮説は、少なくともこの規模では支持されない。10M文字で確認中。

### 10M文字, D=4097 (`--modes optics,cascade:0.5,rff:1,prod`, logs/features_10m_d4096.log)
| 特徴 | train acc1 | acc1 | acc5 | nll |
|---|---|---|---|---|
| **optics** | 31.9 | **31.2** | **58.5** | **3.417** |
| cascade α=0.5 | 31.8 | 31.1 | 58.3 | 3.432 |
| rff σ=1 | 31.6 | 30.9 | 58.2 | 3.429 |
| prod | 30.5 | 30.0 | 57.2 | 3.478 |
- 10M でも順位は同じ。**高次の相互作用を足しても伸びない → 仮説は否定**。train≈val (31.9 vs 31.2) なので過学習ではなく、
  限界は「特徴の種類」ではなく「線形な読み出しの容量 (D 個の特徴 × 語彙)」にある。n-gram はデータに比例して表が育つが、
  リザバーは D を固定すると育たない。これがキュー1の差の正体で、特徴の工夫 (増強、カスケード、ランダム特徴) では縮まない。
- C3 の結論: 光学の特徴は、同じ D のデジタルのランダム特徴と同等か、わずかに良い (acc1 +0.3〜0.4, nll -0.01)。
  「光でも作れて、デジタルのランダム特徴に負けない」とは言える。「光だから良い」とは言えない。2段カスケードは採用しない。

### 混合 (基準に1つ足す。対比較の標準誤差つき)
| 基準 | リザバーを足す (0.56〜13MB) | 同サイズ以下の n-gram を足す (最良) | 判定 |
|---|---|---|---|
| KN 文脈4 剪定1 (32.6MB, 2.694) | -0.011〜-0.013 | KN 文脈2 剪定1 (4.5MB) で -0.023 | 0.56〜4MB は差なし、4.5MB 以上は **n-gram が良い** |
| KN 文脈3 剪定1 (15.2MB, 2.720) | -0.008〜-0.009 | -0.006〜-0.012 | 全て差なし (±0.002) |
| (以前) WB 文脈3 剪定1 (15.2MB, 2.837) | -0.048〜-0.056 | -0.020〜-0.044 | リザバーが良い |
- **WB 相手で見えた「リザバーは安い混合補助」の効き目の大部分は、WB の平滑化の弱さを埋めていただけだった。** KN 相手では、同じバイト数の n-gram と区別できない。
- 最良の nll: n-gram 同士 (KN 文脈2 + 文脈4, 37MB) 2.671 < リザバー入り (KN 文脈4 + D=16385 8bit, 45.8MB) 2.681。
- 残った優位: **合計 1〜3MB の小さい予算で、強く剪定した n-gram に ランク32 (0.56MB) を足す場合**。例: KN 文脈2 剪定20 + ランク32 (1.26MB) 3.224 vs
  n-gram 同士の最良 3.438、KN 文脈2 剪定10 + ランク32 (1.46MB) 3.132 vs 3.213、KN 文脈2 剪定5 + ランク32 (1.83MB) 3.035 vs 3.060。
  ただし剪定の方法が粗い (回数の閾値で切るだけ) ので、相対エントロピー剪定などの良い剪定をすれば、この帯でも n-gram が追いつく可能性がある (未検証)。

### 結論の修正
- 「n-gram に 0.5〜1MB 足すと nll -0.05、同じバイト数の n-gram より良い」(キュー2) は、**弱い n-gram (WB) 相手に限った結論だった**。撤回する。
- リザバーに残る価値: (1) 厳密な追加学習・取り消し・融合、(2) 物理 (光) で作れるランダム特徴で、デジタルのランダム特徴に見劣りしない、
  (3) 粗い素子 (4〜5bit、ばらつき 10%、光子100) で動く、(4) 非常に小さい予算 (〜2MB) で剪定 n-gram の補助になる (未確定)。
