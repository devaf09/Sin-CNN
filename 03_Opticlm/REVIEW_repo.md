## A. 事実の誤り・バグ (直すべきもの)

### A1. 伝播の伝達関数 H の並びが FFT の出力と合っていない (PoC 03〜05、02 の学習・推論の全ファイル)
- `fx = linspace(-N/2, N/2-1) * df` は中心が真ん中の並びだが、`fft2(U)` の出力は周波数 0 が先頭の並び
  (`fftfreq` の並び)。`fftshift` も `ifftshift` もしていないので、H がずれた周波数に掛かっている。
- 数値で確認: 02 の設定 (48×48, 20µm, 633nm, 2mm) で、同じ入力に対する伝播後の強度は、正しい伝播と**相対差 0.99**
  (まったく別物)。02 の H は正しい H を `fftshift` したものと完全に一致する。
- 影響: 学習は「固定の位相の掛け算」として何かを学ぶので、それらしく動いてしまう。だが**実際の光の自由空間伝播ではない**ので、
  出力した位相マスク (phase_masks_2d.npy) を実機に作っても同じ動作はしない。「光で再現」を目標とするなら致命的。
- 修正: `fx = torch.fft.fftfreq(N, d=DX)` にする (PoC 01・02 と opticlm.py はこの形で正しい)。

### A2. 「256 周波数で O(N) に圧縮」の実態
- 位相マップは `Σ freq_x[f]·cos(w_f x) + Σ freq_y[f]·sin(w_f y)` で、**x だけの関数 + y だけの関数**しか作れない
  (2次元の一般的なマスクを作れない)。
- 48画素の格子上では、256 個の周波数のうち異なる値の並びは 49 個しかなく (折り返し)、cos 基底の階数は **25**。
  つまり 256×2 個のパラメータは、1層あたり約 50 次元の自由度しか持たない。「圧縮」というより「表現の制約」。
- 1層 48 画素×2 の値を直接学習するのと同じ表現力なので、sin 基底を使う利点は (この形では) ない。

### A3. 「軽量」の実態: 重さの 98% はデジタル部分
- 02 のチェックポイント 872KB のうち、光学の位相パラメータは 16KB (continuous_freq_weights.bin)。
  残りは `nn.Embedding(V, 2304)` と `nn.Linear(2304, V)` (V≈46 で約 850KB)。語彙が増えると V に比例して増える。
- 計算も同様で、光学部分 (8層) より、2304×V の全結合 (デジタル) が推論の大半を占める。README の
  「時間・電力ともに実質ゼロ」は光学部分だけの話で、SLM の書き換え速度 (kHz〜)、カメラの読み出し、ADC、
  デジタルの出力層のコストが入っていない。

### A4. 「直交位相」は直交していない
- 8 文字の位置に 0, π/4, …, 7π/4 の位相を掛けて**同じ画素に足している**。複素平面で直交するのは π/2 違いの組だけで、
  検出 |U|² の交差項 `2 w_m w_n A_m A_n cos(φ_m − φ_n)` は π/2 違い以外では消えない。π 違いの組 (位置 m と m+4) は
  符号が逆になるだけで区別がつきにくい。
- opticlm は位置ごとに別のランダム位相マスク (画素ごとの位相) を掛けており、高次元ではこちらがほぼ直交になる
  (ランダムベクトルの内積 ≈ 1/√N)。直交性は「1つの位相角」ではなく「空間パターン」で作る必要がある。

### A5. 評価が記憶 (学習データの正解率) だけ
- PoC 04・05・02 は「記憶精度」(学習データでの正解率) だけを表示している。02 のコーパスは 2文 (510 バイト) を3回繰り返した
  もので、100 エポックでの正解率は暗記であり、言語モデルとしての能力は測れていない。検証データでの acc/nll が必要。
- PoC 03 (手書き数字) は学習/テストを分けており、評価として妥当 (このリポジトリで一番きちんとした実験)。

### A6. 細かい点
- 層の間の正規化 (02) や sigmoid の非線形 (03) は受動的な光学素子ではできない (可飽和吸収体や光電変換が必要)。
  「光で再現」と書くなら、どの素子を想定しているかを明記する。
- 01 の sample_corpus.txt は『吾輩は猫である』をブラウザからコピーしたもので、ルビが本文に混ざっている
  (「吾輩わがはい」)。prepare_corpus.py の注意書きのとおり、《》付きの青空文庫テキストを使うべき。
- README の主張「N 次元に膨大な数の直交する sin 波」: 厳密に直交するのは最大 N 本。「ほぼ直交」なら指数的に多く置けるが、
  そのぶん交差 (クロストーク) が雑音として残る。opticlm の実験で、これは容量の上限 (D で頭打ち) として現れている。

## B. 主張の検証状況 (README の「目的」「効果」に対して)
| 主張 | 状況 |
|---|---|
| 再学習コストの低減・パッケージの融合 | **乗算 (位相の加算) による融合は実験が無い**。位相を足すと各パッケージの機能は保たれない (非線形な強度検出を通るため)。一方 opticlm では「統計量の足し算」という別の形で、厳密な融合・取り消しを実現した (誤差 1e-16)。アイディアは形を変えて生きている |
| シード値化で重みを保存しない | opticlm で実現 (光学媒質は seed から再現、保存は読み出し W だけ)。ただし W が大部分 |
| 軽量・高効率 | 同じバイト数では n-gram に負ける (RESULTS.md キュー1)。A3 のとおり 02 もデジタル部分が支配的 |
| 解像度・スケールに依存しない | sin 基底だけでは拡大縮小に不変にならない (拡大はフーリエ空間の縮小)。実験も無い |
| ブラックボックスの回避 (集光点が「丸い」「橙色」に対応) | 集光点が人の概念に対応する仕組みも、検証も無い |
| カオス的な鋭敏性で共通点が鋭くなる | 鋭敏性は汎化と逆向き (入力の小さな違いで出力が大きく変わる)。opticlm では検出器の雑音に強いことが分かっており、むしろ「鋭敏でない」ことが利点になっている |

## C. まだ取り出せるアイディア (opticlm で試せる順)
1. **確信度で切り替える段階処理 (README の「プレビュー層: 荒い→詳細」)**。binpow で分かったとおり、最大スコア (確信度) は
   確率の質をよく表す。これを使って「確信度の低い窓だけ n-gram / 大きい D に回す」「混合の重みを確信度ビンごとに変える」。
   キュー2の混合補助の効きを、追加の重みなしで伸ばせる見込み。最も安く試せる。
2. **パッケージ (UNIX パス型のモジュール) = 分野ごとの統計量**。A, B を分野 (ニュース・ブログ・小説…) ごとに持ち、
   推論時に重み付きで足して解き直す (再学習なしで分野に合わせる)。取り消し・融合が厳密なことを、実用的な形で示せる。
   fit_parallel がそのまま使える (分野ごとに子プロセスで学習して足す)。
3. **「物理であること」の価値を測る対照実験**。同じ D の「ランダムフーリエ特徴 (cos(Rx+b))」や「ランダム射影 + 二乗」で
   同じ閉形式の読み出しを作り、光学の特徴と比べる。光学が同等なら「光でも作れる、ただし特別に良くはない」、
   光学が劣るなら回折の構造 (近接画素の相関) が損をしている、と分かる。設計を変えるときの基準になる。
4. **位相マスクの低パラメータ最適化 (PoC の周波数パラメータの発想)**。読み出しは閉形式のまま、マスクの数個のパラメータ
   (層間距離、マスクの滑らかさ=空間周波数の上限、層数) を検証 nll で外側から探す。勾配なしで、A, B を作り直すだけ。
   「学習しない媒質」でも、作る前の設計の自由度は使える。
5. **全光学の読み出し (PoC 03 の集光点)**。PoC 03 は出力層を持たず、検出面の領域の光量をそのままクラスにしていた。
   opticlm の読み出し W (デジタル) の一部を、最後の層の位相マスクで代わりに行う (少数の主成分だけでも)。
   W のサイズ (サイズ比較での最大の弱点) を減らせる可能性。ただし閉形式の学習は崩れるので、研究としての位置づけ。
6. **フーリエ面 (レンズ) の利用 (02 の lens_phase)**。レンズ1枚で入力のフーリエ変換を作ると、強度は平行移動に不変になる。
   長距離の文脈 (話題) を「位置によらない特徴」として読む手段になる (bag と同じ狙いを、物理的に自然な形で)。
   ただし bag は実日本語で効かなかったので、優先度は低い。
7. フーリエ・メリン変換 (対数極座標) を使えば、README の「スケールに依存しない」を本当に満たす特徴が作れる
   (画像認識に戻るときの候補)。

## D. 推奨
- 02 系を続けるなら、まず A1 (fftfreq) を直し、検証データでの acc/nll を出すこと。直さないまま出力した位相マスクは実機では使えない。
- README の主張は、検証済み (厳密な融合、seed 化、検出器の粗さへの強さ、4〜5bit の W) と、未検証 (スケール不変、
  ブラックボックス回避、時間・電力ゼロ) を分けて書くと、読む人に誤解を与えない。
- 次に試す価値が高いのは C1 (確信度での切替) と C3 (ランダム特徴との対照)。どちらも数十分の実験で白黒がつく。

## E. アイディアの実験結果 (2026-10-13 追記。詳細と数字は RESULTS.md)
| 案 | 結果 |
|---|---|
| C1 確信度で混合の重みを切り替え (プレビュー層) | 効果は小さい (リザバーとの混合で nll -0.004)。n-gram 同士の混合の方が得をし (-0.011)、リザバーの混合の優位は 0.013 → 0.006 に縮む。採用しない |
| C3 光学 vs ランダム特徴 | 光学が最良だが、普通のランダムフーリエ特徴との差は小さい (1M: acc1 +0.4, 10M: +0.3)。「光でも作れて見劣りしない」は言えるが「光だから良い」は言えない |
| C3' 回折なし | 大きく悪化 (D=1025 で acc1 24.8 → 16.7)。回折は「文字の位相パターン → 強度の模様」の変換として必須 |
| C3'' 2段カスケード (強度を位相に書き戻す、高次の相互作用) | 1M・10M とも悪化 (非線形を強くするほど悪い)。容量の壁は「2次止まり」ではなく「線形読み出しの容量 (D×語彙)」 |
| (追加) W の量子化の頑健性 | 4〜5bit + 露光ごとのゲイン、素子のばらつき 10%、検出器 光子100/ADC 6bit の組み合わせで nll +0.04 程度。検証窓10倍・D 2通り・seed 2通りで再現 |

A4 の補足: 「線形なユニタリ (位相板+伝播) の構造は効かない」という私の事前の見立ては誤りだった。回折が無いと、1文字だけの露光は
強度が一定 (|位相|²=1) で情報を持たない。回折は位相の情報を強度に変える役をしていて、特徴の質を決めている。

未着手: C2 (分野ごとのパッケージ) は、CC-100 に分野の情報が無いので、別の分野のコーパス (青空文庫など) を用意してから。
C4 (位相板の低パラメータ最適化) と C5 (全光学の読み出し) は、C3 の結果 (特徴の質より読み出しの容量が限界) から、精度の改善は見込みにくい。
C5 は「W を光で作る」物理実装の研究としては意味がある。

## F. 追記 (2026-10-13): 強い n-gram との比較で、混合補助の優位も消えた
比較相手の n-gram を Kneser-Ney にすると、「リザバーは安い混合補助」という唯一の正の結果も、同じバイト数の n-gram を足すのと差がなくなった
(RESULTS.md)。WB 相手での優位は、WB の平滑化の弱さを補っていただけだった。README の「軽量・高効率」の主張を書き直すときは、
言語モデルの性能ではなく「光で作れる」「粗い素子で動く」「厳密に足し引きできる」を中心にするのが根拠と合う。
